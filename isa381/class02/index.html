Press the right arrow key to walk through the five stops. Each one is a section of Gaddis, Chapter 1.
1. Your browser. You typed on a keyboard (an input device) into Chrome (application software). When you press Run, Colab sends the text of the cell, your source code, over the internet to Google.
2. Google's server. Colab gives your notebook a virtual machine of its own, with a CPU, main memory, and secondary storage, running Linux (an operating system).
3. The interpreter. A program on that machine reads your code, checks its syntax, and translates it into the tiny instructions the CPU understands, one line at a time.
4. CPU and memory. Your code, now a list of instructions, and your data (1200, 950, 1100) sit in main memory. The CPU fetches the next instruction, decodes it, and executes it, working through each function call and each line in turn. This is the stop where time goes: instant for an average, minutes or hours for a large analysis.
5. Back to your screen. The result travels back and Chrome draws it below the cell on your display, an output device.

Colab runs your code “in a virtual machine private to your account,” per Google’s Colab FAQ. The bold terms are the Chapter 1 vocabulary we cover today.

Hardware and Software

Inside the Machine

Hardware: the physical devices that make up a computer. Right arrow steps through them.

Main memoryRAM: the program and its data, while it runs
CPUruns the program
Secondary storagedisk, SSD, flash: keeps data for years
Input deviceskeyboard, mouse, camera
Output devicesdisplay, printer, speakers
Central processing unit (CPU): the part that actually runs programs; nothing runs without it. Once room-sized, now a microprocessor on a small chip.
Main memory (RAM): holds the program while it runs, plus the data it is using. Fast for the CPU to reach, but volatile: erased when the power goes off.
Secondary storage: keeps data for long periods. Programs live here and are loaded into main memory to run. Disk drives (magnetic, spinning), solid-state drives (no moving parts, faster), flash memory (portable).
Input devices collect data from people and other devices. A disk drive counts when it loads a program into memory.
Output devices present what the computer produces: text, images, audio. A disk drive counts when data is saved to it.

Where Does Your Program Live?

Follow the class01 notebook through four moments. The pattern, from Gaddis: programs are stored in secondary storage and copied into main memory each time they run.

1. Saved
Secondary storage
Your notebook file sits in Google Drive. Close the laptop, come back next week: still there.
2. Press Run
Main memory
The interpreter and your cell are copied into the server's RAM. The list monthly_sales now exists, in memory, as the program runs.
3. Runtime restarts
Main memory, erased
Colab reclaims the machine after a while, or you restart it. Everything in RAM is gone: ask for monthly_sales and Python answers NameError.
4. Still saved
Secondary storage
The notebook file was never touched. Re-run the cells and the list is rebuilt from the saved source code.
Volatile
Main memory needs power to hold its contents; temporary by design, and fast (the CPU reaches it directly).
Persistent
Secondary storage keeps data with the power off: magnetic disk drives, solid-state drives (SSD), and portable flash memory such as USB drives.

You will trigger moment 3 yourself in today’s Colab activity. Colab’s virtual machines have limited lifetimes and are recycled when idle, per the Colab FAQ.

How Computers Store Data

Bits and Bytes

All data in a computer is stored as sequences of 0s and 1s. A bit (“binary digit”) holds one of two values: off or on, 0 or 1. A byte is eight bits, enough to store one letter or a small number. Click the bits.

1286432168421
00000000binary
0decimal
 character (ASCII)

Place values double from right to left, so eight bits can represent 28 = 256 different values (0 to 255). The character column uses ASCII, the code that assigns a number to each English letter, digit, and symbol. ASCII only defines 0 to 127: values 0 to 31 are “control codes” (tab, new line), and 128 to 255 are left to other encodings, which is why 255 shows “beyond ASCII”.

Everything Is Bytes

A byte is eight bits, so it holds one of 256 values. Text, numbers, images, and programs are all stored the same way: as bytes.

Text

How a Program Works

Machine Language and the Instruction Set

A CPU performs simple operations on data (read, add, subtract, multiply, divide, store) and understands only machine language: binary instructions from its instruction set. Each brand of CPU has its own set.

What you wrote:

total = 1200 + 950 + 1150
avg = total / 3

Two statements for you. For the CPU, a sequence of tiny instructions, each one a pattern of bits. Meaningful work always takes many of them.

What the CPU sees (our simplified teaching machine):

Address Bits in memory Meaning
00 0001 1010 LOAD the value at address 10
01 0010 1011 ADD the value at address 11
02 0010 1100 ADD the value at address 12
03 0101 1101 DIVIDE by the value at address 13
04 0110 1110 STORE the result at address 14
05 0000 0000 HALT

First four bits: which operation (0001 = LOAD, 0010 = ADD, 0101 = DIVIDE, 0110 = STORE). Last four bits: which address in main memory. The data (1200, 950, 1150, 3) sits at addresses 10 to 13, also as bits.

A simplified teaching machine, not a real chip’s instruction set; x86 and Arm use the same idea with far more operations and longer instructions.

From Python to the Machine

Nobody wants to write 0001 1010. Low-level languages stay close to machine language; high-level languages like Python hide the CPU entirely. Something has to translate.

Compiler
Source code
→
Compiler
→
Machine-language program
→
CPU
Translates the whole program into a separate machine-language file first. That file runs later, as many times as you like, without the compiler present. Used by C, C++, Go, and others.
Interpreter (Python)
Source code
→
Interpreter
→
CPU
Reads one statement, translates it, executes it, then moves to the next. No separate machine-language file; the interpreter must be present every time the program runs. A syntax error stops translation at the statement that breaks the rules.
Assembly
Low-level: one mnemonic per machine instruction (LOAD, ADD, STORE on our teaching machine). Readable, but still one line per CPU operation.
Python
High-level: avg = total / 3 says what you mean; the interpreter produces the many small instructions. (Today’s notebook: dis.dis(…) shows them.)

Definitions follow Gaddis, Chapter 1. Python’s own docs call it interpreted: docs.python.org, “What is Python?”.

Anatomy of a Statement

Click a term on the right to see it in the code: Gaddis’s vocabulary for every program.

import pandas as pd
monthly_sales = [1200, 950, 1150]
if sum(monthly_sales) > 3000:
    print("Above target")

monthly_sales = [1200, 950, 1150]
if sum(monthly_sales) > 3000 
    print("Above target")
  File "<cell>", line 3
    if sum(monthly_sales) > 3000
                                ^
SyntaxError: expected ':'
Keyword: a word with a reserved meaning in the language. import, as, if. Python has 35 of them; you cannot use them as names.
Operator: a symbol that performs an operation on data. = assigns, > compares; + - * / do arithmetic.
Statement: one individual instruction in a high-level language. Each line here is one.
Syntax: the rules for how statements are written. The colon after if and the four-space indent are Python's rules, not decoration.
Source code: the statements you write, all of them, before any translation happens.
Syntax error: a broken rule. The interpreter refuses to translate; nothing runs. Click to remove the colon.

The 35 keywords are listed in the Python Language Reference. print and sum are built-in functions, not keywords. The error message is Python’s actual output for a missing colon.

Summary of Main Points

By now, you should be able to do the following:

  • Name the hardware: the CPU runs programs; main memory holds the running program and its data (and forgets when the power is off); secondary storage keeps files; input and output devices connect the machine to people.

  • Sort software into applications and system software (operating systems, utilities, development tools such as the Python interpreter).

  • Explain that all data is bits and bytes: eight bits, 256 values, one character per byte in ASCII; numbers in binary; pixels as three bytes.

  • Trace the fetch-decode-execute cycle through machine language from a CPU’s instruction set, and say why nobody writes it: high-level languages plus an interpreter (Python) or a compiler do the translation.

  • Read a Python statement and point at its keywords, operators, and syntax, and recognize a syntax error when the interpreter reports one.
